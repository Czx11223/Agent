## 1. 项目背景与业务目标

### 1.1 项目背景

随着智慧医院建设的推进，门诊分诊与预问诊环节的效率直接影响患者就医体验。当前存在三大痛点：

1. **挂号困难**：大量患者缺乏医学常识，挂号时不清楚应就诊哪个科室。
2. **导诊台拥堵**：高峰期排队严重，导诊人力紧张。
3. **医生问诊耗时**：医生需花较长时间询问基本信息，压缩了诊疗沟通时间。

多轮对话技术为解决上述问题提供了新途径：系统通过多轮追问逐步澄清患者的症状、部位、持续时间与既往病史，自动生成结构化预问诊报告，并基于症状特征推荐就诊科室。近年来大语言模型在医疗对话任务上表现不断提升，CMB 等中文医疗评测基准为评估模型医疗对话能力提供了公开依据。基于浏览器的 Web 应用无需安装、跨平台、便于访问，适合在医院公众号、自助机等场景推广使用。

### 1.2 业务目标

**总体目标**：开发一款多轮对话式智能问诊导诊 Agent Web 应用，以自然语言对话方式追问患者症状信息，追问完成后自动生成结构化预问诊报告并推荐就诊科室，报告可供患者挂号与医生接诊参考。

**具体业务目标**：

| 编号 | 业务目标 | 衡量指标 |
| --- | --- | --- |
| BG-1 | 通过多轮追问覆盖全部关键问诊要素 | 关键信息追问覆盖率 ≥ 90% |
| BG-2 | 输出结构化、可溯源的预问诊报告 | 报告字段完整率 ≥ 90% |
| BG-3 | 准确推荐 Top3 就诊科室 | 科室推荐 Top3 准确率 ≥ 80% |
| BG-4 | 保障对话响应实时性 | 平均响应时间 ≤ 5 秒 |
| BG-5 | 识别急重症并拦截提示急诊 | 急重症识别规则 100% 生效 |
| BG-6 | 全程严格免责，不做诊断、不开药 | 合规约束 100% 生效 |
| BG-7 | 保障患者敏感健康数据安全合规 | 无数据泄露风险项 |

### 1.3 项目意义

- **业务价值**：为患者提供门诊前的智能预问诊与科室推荐服务，减少挂错号与重复排队，提高医患沟通效率。
- **技术价值**：实践多轮对话管理、槽位填充、提示词工程与大模型应用开发全流程，掌握对话式智能体的核心技术栈。
- **社会价值**：优化医院分诊流程，缓解导诊人力紧张，助力智慧医院与分级诊疗建设。

## 2. 产品定位与使用场景

### 2.1 产品形态

- **名称**：预问诊医助（智能问诊导诊 Agent）。
- **形态**：B/S 前后端分离的响应式 Web 应用，适配 PC 端与移动端主流浏览器。
- **服务边界**：仅提供挂号与接诊参考的预问诊服务，不构成医学诊断。

### 2.2 使用场景

| 场景编号 | 场景描述 | 使用端 |
| --- | --- | --- |
| SC-1 | 患者到院前通过手机浏览器在线完成预问诊 | 移动端 |
| SC-2 | 患者在自助机 / 导诊台通过浏览器完成预问诊 | 触屏设备 |
| SC-3 | 医生接诊前查看患者的结构化预问诊报告 | 桌面端 |
| SC-4 | 开发团队跑批评测，验证追问覆盖率与推荐准确率 | 桌面端 / 命令行 |

## 3. 用户角色与权限

| 角色 | 说明 | 核心权限 | 数据权限边界 |
| --- | --- | --- | --- |
| 患者（普通用户） | 使用预问诊与科室推荐服务的最终用户 | 注册/登录、发起并管理自己的会话、查看/复制/导出自己的预问诊报告、查看科室推荐 | 仅本人数据 |
| 医生（接诊参考方，仅查看） | 接诊前查看患者预问诊报告 | 经授权查看指定患者的预问诊报告 | 由系统按会话授权，最小化披露 |
| 系统管理员 | 维护系统运行与评测 | 用户管理、会话与日志审计、评测触发、规则（症状—科室映射、急重症词表、免责声明）维护 | 系统级 |
| 评测人员（开发侧） | 批量评测模型对话能力 | 提交测试问诊集、查看评测报告与 bad case | 评测数据 |

> 注：医生查看角色本期可为"只读报告链接授权"形式，重点保障最小化披露与留痕。

## 5. 功能需求

> 需求编号规则：FR（功能需求）/ NFR（非功能需求）/ PR（隐私与安全）/ RTL（合规与免责）。

### 5.1 用户中心模块

| 需求编号 | 需求名称 | 需求描述 | 优先级 |
| --- | --- | --- | --- |
| FR-01 | 用户注册 | 支持手机号/用户名 + 密码注册，密码需强度校验，手机号唯一 | 高 |
| FR-02 | 用户登录 | 支持账号密码登录，JWT 会话鉴权，登录态过期自动续期 | 高 |
| FR-03 | 退出登录 | 安全登出并失效令牌，清除前端内存中的敏感会话数据 | 高 |
| FR-04 | 个人中心 | 展示/维护基本信息，可查看本人历史会话与报告列表 | 中 |
| FR-05 | 会话与记录管理 | 支持会话列表展示、切换、新建与删除（回收站/软删） | 中 |

### 5.2 对话中心模块（核心）

| 需求编号 | 需求名称 | 需求描述 | 优先级 |
| --- | --- | --- | --- |
| FR-10 | 发起预问诊会话 | 用户进入对话页自动/手动开启新一轮预问诊会话，会话状态初始化为"问诊中" | 高 |
| FR-11 | 多轮预问诊追问 | 围绕"主要症状→部位→持续时间→伴随症状→既往史"追问链逐项提问，采用召回式追问策略 | 高 |
| FR-12 | 追问完成度判断 | 基于已填充槽位判断信息是否齐备；不足时继续追问，齐备后转入报告生成 | 高 |
| FR-13 | 槽位填充 | 从用户句中抽取并填充以下症状要素槽位：主要症状、部位、持续时间、伴随症状、既往史（含过敏史）；支持冲突/补充合并 | 高 |
| FR-14 | 指代消解 | 支持指代理解，如"也是这里疼"中"这里/也"的正确消解 | 高 |
| FR-15 | 上下文记忆与历史 | 维护对话记忆，携带上文作为追问与生成的上下文；服务端持久化会话历史 | 高 |
| FR-16 | 情绪识别与安抚 | 识别患者焦虑、疼痛等情绪，及时给予共情安抚后再继续追问 | 高 |
| FR-17 | 急重症识别与急诊提示 | 识别到胸痛、呼吸困难等急重症状表述，立即提示患者紧急就医或拨打 120 并中止常规延长追问（见 RTL-02） | 高 |
| FR-18 | 流式响应 | 后端 SSE 流式返回对话内容，Token 级边生成边展示 | 高 |
| FR-19 | 会话切换 | 支持在多轮回话列表间切换，切换后恢复对应上下文继续对话 | 中 |
| FR-20 | 越界问题拒答 | 对索要诊断结论、处方等超出导诊范围的问题拒答并引导就医（见 RTL-03） | 高 |

### 5.3 报告中心模块

| 需求编号 | 需求名称 | 需求描述 | 优先级 |
| --- | --- | --- | --- |
| FR-30 | 结构化预问诊报告生成 | 追问完成后由 LLM 生成含主诉、现病史、过敏史、既往史、伴随症状等字段的结构化报告 | 高 |
| FR-31 | 科室推荐 | 基于症状—科室映射表输出 Top3 推荐就诊科室及理由 | 高 |
| FR-32 | 报告溯源标注 | 报告中各项信息标注"来源于患者口述"，逐项可溯源（见 PR-04） | 高 |
| FR-33 | 免责声明展示 | 报告页显著展示免责声明：仅作挂号/接诊参考，不构成诊断与处方（见 RTL-01） | 高 |
| FR-34 | Markdown 渲染 | 报告与对话内容支持 Markdown 渲染 | 中 |
| FR-35 | 报告复制/导出 | 支持一键复制、导出（Markdown/文本）预问诊报告 | 中 |

### 5.4 评测中心模块

| 需求编号 | 需求名称 | 需求描述 | 优先级 |
| --- | --- | --- | --- |
| FR-40 | 测试问诊集管理 | 维护不少于 100 条的测试问诊对话集（含标准答案标注） | 高 |
| FR-41 | 批量跑批评测 | 对测试集批量执行交互评测，自动统计三项指标 | 高 |
| FR-42 | 指标统计 | 统计关键信息追问覆盖率、报告字段完整率、科室推荐 Top3 准确率及平均响应时间 | 高 |
| FR-43 | BadCase 分析 | 记录失败用例（bad case），支持定位追问策略/提示词问题并迭代 | 中 |

### 5.5 需求优先级汇总

- **P0（MVP 必做）**：FR-01/02/03、FR-10~18、FR-20、FR-30/31/32/33、FR-40/41/42。
- **P1（重要）**：FR-04/05、FR-19、FR-34/35、FR-43。
- **P2（增强，后续迭代）**：多语言、语音输入、报告导出 PDF 等。

## 7. 安全、合规与隐私需求

### 7.1 患者健康数据隐私（PR）

| 编号 | 需求 | 说明 |
| --- | --- | --- |
| PR-01 | 传输加密 | 全站 HTTPS 加密传输，禁止明文传输敏感症状/健康信息 |
| PR-02 | 存储安全 | 数据库对敏感健康信息列加密（应用层加密，秘钥托管于安全环境） |
| PR-03 | 最小化收集 | 仅收集完成预问诊所必需的字段，不收多余敏感信息 |
| PR-04 | 数据溯源 | 报告中每项信息标注来源为患者口述，逐项可溯源 |
| PR-05 | 访问控制 | 用户仅能访问本人数据；角色权限最小化；敏感接口鉴权与越权校验 |
| PR-06 | 日志脱敏 | 日志与上报数据对健康信息进行脱敏处理 |
| PR-07 | 数据合规 | 遵守《个人信息保护法》《数据安全法》等法规，提供隐私政策与知情同意 |
| PR-08 | 清除与导出 | 支持用户导出、删除本人数据（含完整删除） |

### 7.2 内容安全

| 编号 | 需求 | 说明 |
| --- | --- | --- |
| PR-20 | 敏感内容过滤 | 对大模型输入/输出进行敏感词与违规内容过滤 |
| PR-21 | 提示词注入防范 | 对用户输入做注入指令检测，防止绕过系统人设约束与边界 |
| PR-22 | 模型幻觉防控 | 培训后校验：科室推荐基于映射规则约束，避免模型自由发挥造成幻觉规则外输出 |

### 7.3 免责与合规规则（RTL）

| 编号 | 规则 | 内容 | 触发/执行位置 |
| --- | --- | --- | --- |
| RTL-01 | 免责声明 | Agent 提供的预问诊报告与科室推荐仅供挂号和接诊参考，不构成医学诊断结论或治疗建议；AI 回答仅供参考，最终诊疗方案以执业医师判断为准 | 对话入口 + 报告页显著常驻展示 |
| RTL-02 | 急重症拦截 | 识别到胸痛、呼吸困难等急重症状表述时，提示"建议立即急诊就医或拨打 120"，停止常规追问 | Agent 编排层规则引擎，词表+LLM 双保险 |
| RTL-03 | 越界拒答 | 超出导诊范围的问题（索要诊断结论、处方、剂量等）一律拒答并引导就医；**不做诊断、不开药** | 系统提示词 + 人设边界 + 输出守卫 |

## 9. 约束条件与非目标

### 9.1 技术约束

- 语言：Python 3.12+；后端：FastAPI；Agent 框架：AgentScope；LLM：国内可直连的 OpenAI 兼容 API；前端：React + TailwindCSS / Ant Design；数据库：sqlite3；协议：RESTful + SSE。

### 9.2 非目标（本期不做）

- 不提供在线支付、线上处方、挂号交易闭环。
- 不直接对接医院 HIS/LIS 系统（本期为独立 demo 级应用）。
- 不做电话/语音实时问诊（语音输入可为后续增强项）。

## 11. 验收标准

1. 五大功能模块（用户中心、对话中心、报告中心、评测中心、急重症/免责）可用且满足 P0 需求。
2. 平均响应时间 ≤ 5 秒。
3. 科室推荐 Top3 准确率 ≥ 80%。
4. 关键信息追问覆盖率 ≥ 90%。
5. 报告字段完整率 ≥ 90%。
6. 主浏览器（Chrome/Firefox/Safari/Edge）最新两个大版本正常兼容。
7. 免责声明、急重症拦截、越界拒答、数据加密与溯源等安全合规要求全部生效并通过核查。
8. 评测集 ≥ 100 条并产出评测报告。

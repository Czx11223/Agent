# 医疗问诊对话语料：获取 · 清洗 · 症状抽取与科室映射

> 交付说明：本任务面向 `YouTaoBaBa/Chinese-Dialogue-Dataset` 指向的中文医疗问诊数据。**重要澄清**：该 GitHub 仓库本身**不包含数据文件**，只是 README 索引页，真实医疗数据为**天池**数据集 `chinese medical dialogue`（`dataId=90163`）。以下方案基于该数据集的文档化结构（6 个科室 CSV、字段 `department/title/ask/answer`、合计约 79.2 万条、zip 约 138MB）。样例均为**去隐私的模拟演示数据**，不含真实患者信息。

## 二、清洗管线（clean_pipeline）

```
corpus_raw/（6 个科室 CSV）
   │ clean_dialogue.py
   ▼
cleaned_dialogue.csv（标准化样本）
   │ symptom_extract.py
   ▼
symptom_lexicon.csv（症状-词表-科室统计）
```

### 运行命令
```powershell
# 1) 清洗：输入 zip 或目录或 csv，输出标准样本
python clean_pipeline/clean_dialogue.py --input corpus_raw --out cleaned_dialogue.csv
python clean_pipeline/clean_dialogue.py --input corpus_raw/IM_内科.csv --out cleaned_dialogue.csv
python clean_pipeline/clean_dialogue.py --demo --out sample_cleaned.csv   # 内置模拟样例演示

# 2) 抽取症状词表 + 症状-科室映射表（读清洗后样本）
python clean_pipeline/symptom_extract.py --input cleaned_dialogue.csv --out symptom_lexicon.csv --map-out symptom_dept_map.csv
```

### 清洗逻辑（`clean_dialogue.py`）
1. **脱敏** `desensitize()`：对手机号/座机/身份证/邮箱/车牌做正则替换为 `[手机号]` 等占位（`blacklist.PII_PATTERNS`）。
2. **黑名单过滤** `blacklist.py`：
   - `PRESCRIPTION_WORDS`（用药/处方，命中→丢弃 `reason=prescription`）；
   - `DIAGNOSIS_WORDS`（诊断断言，命中→丢弃 `reason=diagnosis`）；
   - `EMERGENCY_WORDS`（急重症，仅**标记**不丢弃，且急重症样本**豁免**处方/诊断过滤）；
   - `SKIP_MARKERS` / 空值 / 过短（`empty_or_broken` / `too_short`）。
3. **主诉提取** `extract_complaint()`：在患者 `ask` 中按标点切句，取 3~40 字的短句作为“患者主诉”。
4. **追问识别** `is_followup()`：医生 `answer` 含疑问句式（多少/哪里/有没有/疼不疼…）→ 归为“医生追问”；否则进入“患者补充/说明”栏。
5. **急重症标记**：命中胸痛/呼吸困难/大出血等 → `is_emergency=1`。

### 全量清洗结果（corpus_raw 全量执行）
| 指标 | 数值 |
|---|---|
| 原始记录总数 | 792,099 |
| **清洗后保留（可入库）** | **490,838** |
| 其中急重症标记（`is_emergency=1`） | 33,250 |
| 拒绝分布 | `prescription` 114,828 ・ `diagnosis` 49,406 ・ `empty_or_broken` 44,276 ・ `too_short` 92,751 |

> 编码说明：天池原始 CSV 为 GBK 编码，且个别文件含极少非法字节导致**整文件严格 GBK 解码失败**。`clean_dialogue.py::_decode_bytes()` 采用“逐编码严格尝试 → utf-8/gbk 容错解码中选替换字符最少者”的策略，确保中文完整保留而非整段乱码（此前一次全量清洗因该问题产生整列 `替换字符`，已修复重跑）。

### 输出字段规范（cleaned_dialogue.csv）
| 字段 | 含义 | 说明 |
|---|---|---|
| `case_id` | 样本编号 | `Cxxxxxx`（入库）/ `dropped_xxxx`（被拒） |
| `source_department` | 来源科室 | 原 `department` 字段 |
| `patient_complaint` | 患者主诉 | 患者提问提炼的主诉短句 |
| `doctor_followup` | 医生追问 | answer 中疑问/澄清句（可为空=单轮无追问） |
| `patient_fill` | 患者补充 | 原始单轮无多轮补充，此处常为空或医生说明文本 |
| `is_emergency` | 是否急重症 | `1/0` |
| `filter_reason` | 拒绝原因 | 空=可入库；`prescription/diagnosis/empty_or_broken/too_short` |

> 诚实说明：原始数据为**单轮问答**，本身不含“患者补充”多轮。因此 `doctor_followup`/`patient_fill` 在多数样本为“医生内容 / 空”。要得到完整【主诉→追问→补充】多轮样本，建议在本项目 Agent（按 07 追问要素清单）或后续模型追问阶段、用清洗后的主诉为切入点重构，而非指望原始 CSV 直接提供多轮对话。

## 三、语料库规范

- **合格样本判定**：`ask`、`answer` 均有实质内容；`patient_complaint` 长度 ≥3；`filter_reason` 为空；不含处方/诊断断言；已脱敏。
- **黑名单（禁止入库）**：见 `blacklist.py`，主类为①处方/用药②诊断/确诊断言。急重症文本仅标不拒。
- **质量指标建议**：清洗后保留率（kept/total）、急重症样本命中率、黑名单误伤率（可用抽检人工标注互为参照）。

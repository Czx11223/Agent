| 文档版本 | V1.0.0 | 文档日期 | 2026-10-08 |

---

## 1. 设计总览

### 1.1 设计约定

| 约定项 | 说明 |
| --- | --- |
| 主键 | 统一采用 `INTEGER PRIMARY KEY AUTOINCREMENT`，另提供 `code` 业务编号用于识别 |
| 时间 | 统一存储 UTC 时间，格式 `TEXT (ISO8601, 'YYYY-MM-DDTHH:MM:SS.sssZ')`，展示层转本地时区 |
| 软删除 | 核心表使用 `deleted` 逻辑删除标记，避免误删历史数据 |
| 敏感信息 | 涉及健康/症状类的关键字段经应用层加密后写入（列加密） |
| 外键 | 使用逻辑引用 `*_code`/`*_id`，开启 `PRAGMA foreign_keys=ON` 强制约束 |
| 索引 | 对高频查询、外键关联、状态过滤列建索引 |
| 时区 | `created_at`/`updated_at` 由应用层统一写入 |

### 1.2 表清单

| 表名 | 说明 | 主用途 |
| --- | --- | --- |
| `user` | 用户表 | 注册登录、个人数据归属 |
| `conversation` | 会话表 | 每次预问诊对话会话 |
| `message` | 对话消息表 | 会话内逐条对话记录 |
| `pre_diagnose_report` | 预问诊报告表 | 结构化预问诊报告与科室推荐 |
| `evaluation` | 评测记录表 | 评测集跑批与指标结果 |

### 1.3 表关系（ER 概览）

```
user (1) ──<1:N>── conversation (1) ──<1:N>── message
                      │
                      └─────<1:1>── pre_diagnose_report ──（关联 symptom 快照）
user (1) ──<1:N>── evaluation（评测由评测人员触发，记录被评测样本与结果）
```

- 一个用户可有多个会话；一个会话可有多个消息、对应**至多一份**预问诊报告。
- 报告中的症状要素以**快照列**保存（关键字段 JSON 序列化），保证报告可溯源且不受会话后续变更影响。

## 2. 表结构详细设计

### 2.1 用户表 `user`

存储用户账号与认证信息，保障患者数据归属与安全。

| 字段名 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| `id` | INTEGER | PK, AUTOINCREMENT | 自增主键 |
| `code` | TEXT | NOT NULL, UNIQUE | 业务编号（如 `U20261008001`） |
| `username` | TEXT | NOT NULL, UNIQUE | 登录用户名（唯一） |
| `phone` | TEXT | UNIQUE | 手机号（唯一，可空，用于注册方式二） |
| `password_hash` | TEXT | NOT NULL | 密码哈希（bcrypt，勿存明文） |
| `display_name` | TEXT |  | 显示名称 |
| `avatar_url` | TEXT |  | 头像地址（可空） |
| `role` | TEXT | NOT NULL, DEFAULT 'patient' | 角色：`patient`/`doctor`/`admin`/`evaluator` |
| `status` | TEXT | NOT NULL, DEFAULT 'active' | 状态：`active`/`disabled` |
| `last_login_at` | TEXT |  | 最近登录时间（ISO8601） |
| `deleted` | INTEGER | NOT NULL, DEFAULT 0 | 软删标记：0 未删 / 1 已删 |
| `created_at` | TEXT | NOT NULL | 创建时间 |
| `updated_at` | TEXT | NOT NULL | 更新时间 |

**索引**：`idx_user_username(username)`、`idx_user_phone(phone)`、`idx_user_code(code)`。
**存储**：`password_hash` 仅存哈希；不与健康信息同表，降低暴露面。

---

### 2.2 会话表 `conversation`

记录一次预问诊对话会话的生命周期与追问要素进度。

| 字段名 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| `id` | INTEGER | PK, AUTOINCREMENT | 自增主键 |
| `code` | TEXT | NOT NULL, UNIQUE | 业务编号（如 `C20261008001`） |
| `user_id` | INTEGER | NOT NULL, FK→user.id | 所属用户 |
| `title` | TEXT |  | 会话标题（可自动取首句主诉） |
| `status` | TEXT | NOT NULL, DEFAULT 'diagnosing' | 会话状态：`diagnosing` 问诊中 / `completed` 已结案 / `terminated` 已终止 / `emergency` 急重症拦截 |
| `started_at` | TEXT | NOT NULL | 会话开始时间 |
| `ended_at` | TEXT |  | 会话结束时间（可空） |
| `slot_state` | TEXT |  | 追问要素槽位快照：JSON，含 症状/部位/持续时间/伴随症状/既往史 等要素及完成度 |
| `ask_progress` | TEXT | DEFAULT '{}' | 追问进度：JSON，记录各要素是否已追问/已获取（用于覆盖率统计） |
| `emergency_flag` | INTEGER | NOT NULL, DEFAULT 0 | 急重症触发标记：0 未触发 / 1 已触发急诊提示 |
| `deleted` | INTEGER | NOT NULL, DEFAULT 0 | 软删标记 |
| `created_at` | TEXT | NOT NULL | 创建时间 |
| `updated_at` | TEXT | NOT NULL | 更新时间 |

**索引**：`idx_conv_user(user_id)`、`idx_conv_user_status(user_id, status)`、`idx_conv_code(code)`。
**说明**：`slot_state` 持久化对话填充的要素槽位，支持会话切换恢复上下文与评测覆盖率统计；`ask_progress` 供关键信息追问覆盖率计算。

---

### 2.3 对话消息表 `message`

存储会话内每一条用户消息与系统回复，构成对话历史与流式回放依据。

| 字段名 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| `id` | INTEGER | PK, AUTOINCREMENT | 自增主键 |
| `code` | TEXT | NOT NULL, UNIQUE | 业务编号（如 `M20261008001`） |
| `conversation_id` | INTEGER | NOT NULL, FK→conversation.id | 所属会话 |
| `sender` | TEXT | NOT NULL | 消息方：`user` 用户 / `agent` 医助 |
| `content` | TEXT | NOT NULL | 消息正文（含 Markdown） |
| `content_type` | TEXT | NOT NULL, DEFAULT 'text' | 内容类型：`text`(纯文本) / `markdown` / `report`(指向报告) |
| `slot_delta` | TEXT |  | 本条消息抽取的槽位增量：JSON（如 `{"部位":"胸口"}`） |
| `emotion` | TEXT |  | 识别到的情绪标记（如 `anxiety`/`pain`/`none`，可空） |
| `emergency_hit` | INTEGER | NOT NULL, DEFAULT 0 | 本条是否命中急重症拦截 |
| `extra` | TEXT |  | 扩展字段（JSON，如 token 数、LLM 元信息） |
| `created_at` | TEXT | NOT NULL | 消息时间 |

**索引**：`idx_msg_conv(conversation_id)`、`idx_msg_conv_time(conversation_id, created_at)`、`idx_msg_code(code)`。
**说明**：`sender`+`content` 构成可回放的对话历史；`slot_delta`、`emotion`、`emergency_hit` 支撑评测与溯源。

---

### 2.4 预问诊报告表 `pre_diagnose_report`

存储结构化预问诊报告与科室推荐结果，报告各要素以快照保存并可溯源。

| 字段名 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| `id` | INTEGER | PK, AUTOINCREMENT | 自增主键 |
| `code` | TEXT | NOT NULL, UNIQUE | 业务编号（如 `R20261008001`） |
| `conversation_id` | INTEGER | NOT NULL, FK→conversation.id, UNIQUE | 关联会话（一个会话至多一份报告） |
| `user_id` | INTEGER | NOT NULL, FK→user.id | 报告归属用户 |
| `chief_complaint` | TEXT |  | 主诉（可含加密/标记） |
| `present_illness` | TEXT |  | 现病史（症状、部位、持续时间等追述） |
| `accompanying_symptom` | TEXT |  | 伴随症状 |
| `past_history` | TEXT |  | 既往史 |
| `allergy_history` | TEXT |  | 过敏史 |
| `symptom_json` | TEXT |  | 要素槽位结构化快照：JSON（五类要素的最终值，用于字段完整率统计与溯源） |
| `recommend_dept_top3` | TEXT |  | 推荐科室 Top3：JSON 数组（含科室名与推荐理由），如 `[{"dept":"心内科","reason":"..."}]` |
| `top3_accuracy` | INTEGER |  | 评测用：本报告 Top3 是否命中标准科室（0/1，评测跑批时回填） |
| `emergency_flag` | INTEGER | NOT NULL, DEFAULT 0 | 报告是否含急诊提示标记 |
| `disclaimer` | TEXT | NOT NULL, DEFAULT 同默认文案 | 报告页免责声明文案快照 |
| `status` | TEXT | NOT NULL, DEFAULT 'draft' | 状态：`draft`(草稿) / `generated`(已生成) / `reviewed`(已复核) |
| `deleted` | INTEGER | NOT NULL, DEFAULT 0 | 软删标记 |
| `created_at` | TEXT | NOT NULL | 生成时间 |
| `updated_at` | TEXT | NOT NULL | 更新时间 |

**索引**：`idx_report_user(user_id)`、`idx_report_conv(conversation_id)`、`idx_report_code(code)`。
**说明**：
- `conversation_id` 唯一约束保证"一会话一报告"，避免重复生成。
- 所有病史字段均来自患者口述、逐项可溯源；`disclaimer` 快照需显著展示（合规 RTL-01）。
- 若命中急重症，报告 `emergency_flag=1` 并提示急诊。

---

### 2.5 评测记录表 `evaluation`

存储评测集单条样本的评测结果，支撑三项核心指标（追问覆盖率、字段完整率、Top3 准确率）与 bad case 分析。

| 字段名 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| `id` | INTEGER | PK, AUTOINCREMENT | 自增主键 |
| `code` | TEXT | NOT NULL, UNIQUE | 业务编号（如 `E20261008001`） |
| `batch_code` | TEXT | NOT NULL | 评测批次号（一次跑批共用一个批次） |
| `test_case_id` | TEXT | NOT NULL | 测试问诊集用例编号 |
| `user_id` | INTEGER |  | 触发评测的用户（可空，批影响评价人员） |
| `conversation_id` | INTEGER | FK→conversation.id | 关联会话（若非交互式评测则空） |
| `report_id` | INTEGER | FK→pre_diagnose_report.id | 关联生成的报告（可空） |
| `input_text` | TEXT | NOT NULL | 评测输入（患者主诉/语句） |
| `input_text_enc` | TEXT |  | 输入加密存储（可选，含敏感信息时） |
| `expected_dept` | TEXT | NOT NULL | 标准答案：期望科室 |
| `expected_fields` | TEXT |  | 标准答案：期望要素清单（JSON） |
| `top3_accuracy` | INTEGER | NOT NULL, DEFAULT 0 | 是否命中：0/1（科室推荐 Top3 准确率） |
| `field_coverage` | REAL | DEFAULT 0 | 关键信息追问覆盖率：0~1（命中要素/期望要素） |
| `report_completeness` | REAL | DEFAULT 0 | 报告字段完整率：0~1（非空字段/必填字段） |
| `avg_response_time` | REAL |  | 平均响应时间（秒），用于响应时延评估 |
| `bad_case_flag` | INTEGER | NOT NULL, DEFAULT 0 | 是否 bad case：1 表示未达标需分析 |
| `reason` | TEXT |  | 未达标原因/备注（bad case 定位） |
| `status` | TEXT | NOT NULL, DEFAULT 'pending' | 状态：`pending` / `running` / `done` / `failed` |
| `created_at` | TEXT | NOT NULL | 记录创建时间（跑批评测生成） |
| `updated_at` | TEXT | NOT NULL | 更新时间 |

**索引**：`idx_eval_batch(batch_code)`、`idx_eval_case(test_case_id)`、`idx_eval_bad(batch_code, bad_case_flag)`、`idx_eval_code(code)`。
**说明**：三项指标既可逐条（`field_coverage`/`report_completeness`/`top3_accuracy`）存储，也可在评测汇总层求均值；`bad_case_flag`+`reason` 支撑 bad case 定位与提示词迭代。

## 3. DDL 建表脚本（sqlite3）

```sql
PRAGMA foreign_keys = ON;

-- 用户表
CREATE TABLE IF NOT EXISTS user (
    id              INTEGER PRIMARY KEY AUTOINCREMENT,
    code            TEXT    NOT NULL UNIQUE,
    username        TEXT    NOT NULL UNIQUE,
    phone           TEXT    UNIQUE,
    password_hash   TEXT    NOT NULL,
    display_name    TEXT,
    avatar_url      TEXT,
    role            TEXT    NOT NULL DEFAULT 'patient',
    status          TEXT    NOT NULL DEFAULT 'active',
    last_login_at   TEXT,
    deleted         INTEGER NOT NULL DEFAULT 0,
    created_at      TEXT    NOT NULL,
    updated_at      TEXT    NOT NULL
);
CREATE INDEX idx_user_username ON user(username);
CREATE INDEX idx_user_phone    ON user(phone);
CREATE INDEX idx_user_code     ON user(code);

-- 会话表
CREATE TABLE IF NOT EXISTS conversation (
    id             INTEGER PRIMARY KEY AUTOINCREMENT,
    code           TEXT    NOT NULL UNIQUE,
    user_id        INTEGER NOT NULL REFERENCES user(id),
    title          TEXT,
    status         TEXT    NOT NULL DEFAULT 'diagnosing',
    started_at     TEXT    NOT NULL,
    ended_at       TEXT,
    slot_state     TEXT,
    ask_progress   TEXT    DEFAULT '{}',
    emergency_flag INTEGER NOT NULL DEFAULT 0,
    deleted        INTEGER NOT NULL DEFAULT 0,
    created_at     TEXT    NOT NULL,
    updated_at     TEXT    NOT NULL
);
CREATE INDEX idx_conv_user        ON conversation(user_id);
CREATE INDEX idx_conv_user_status ON conversation(user_id, status);
CREATE INDEX idx_conv_code        ON conversation(code);

-- 对话消息表
CREATE TABLE IF NOT EXISTS message (
    id               INTEGER PRIMARY KEY AUTOINCREMENT,
    code             TEXT    NOT NULL UNIQUE,
    conversation_id  INTEGER NOT NULL REFERENCES conversation(id),
    sender           TEXT    NOT NULL,
    content          TEXT    NOT NULL,
    content_type     TEXT    NOT NULL DEFAULT 'text',
    slot_delta       TEXT,
    emotion          TEXT,
    emergency_hit    INTEGER NOT NULL DEFAULT 0,
    extra            TEXT,
    created_at       TEXT    NOT NULL
);
CREATE INDEX idx_msg_conv      ON message(conversation_id);
CREATE INDEX idx_msg_conv_time ON message(conversation_id, created_at);
CREATE INDEX idx_msg_code      ON message(code);

-- 预问诊报告表
CREATE TABLE IF NOT EXISTS pre_diagnose_report (
    id                   INTEGER PRIMARY KEY AUTOINCREMENT,
    code                 TEXT    NOT NULL UNIQUE,
    conversation_id      INTEGER NOT NULL UNIQUE REFERENCES conversation(id),
    user_id              INTEGER NOT NULL REFERENCES user(id),
    chief_complaint      TEXT,
    present_illness      TEXT,
    accompanying_symptom TEXT,
    past_history         TEXT,
    allergy_history      TEXT,
    symptom_json         TEXT,
    recommend_dept_top3  TEXT,
    top3_accuracy        INTEGER,
    emergency_flag       INTEGER NOT NULL DEFAULT 0,
    disclaimer           TEXT    NOT NULL,
    status               TEXT    NOT NULL DEFAULT 'draft',
    deleted              INTEGER NOT NULL DEFAULT 0,
    created_at           TEXT    NOT NULL,
    updated_at           TEXT    NOT NULL
);
CREATE INDEX idx_report_user ON pre_diagnose_report(user_id);
CREATE INDEX idx_report_conv ON pre_diagnose_report(conversation_id);
CREATE INDEX idx_report_code ON pre_diagnose_report(code);

-- 评测记录表
CREATE TABLE IF NOT EXISTS evaluation (
    id                 INTEGER PRIMARY KEY AUTOINCREMENT,
    code               TEXT    NOT NULL UNIQUE,
    batch_code         TEXT    NOT NULL,
    test_case_id       TEXT    NOT NULL,
    user_id            INTEGER REFERENCES user(id),
    conversation_id    INTEGER REFERENCES conversation(id),
    report_id          INTEGER REFERENCES pre_diagnose_report(id),
    input_text         TEXT    NOT NULL,
    input_text_enc     TEXT,
    expected_dept      TEXT    NOT NULL,
    expected_fields    TEXT,
    top3_accuracy      INTEGER NOT NULL DEFAULT 0,
    field_coverage     REAL    DEFAULT 0,
    report_completeness REAL   DEFAULT 0,
    avg_response_time  REAL,
    bad_case_flag      INTEGER NOT NULL DEFAULT 0,
    reason             TEXT,
    status             TEXT    NOT NULL DEFAULT 'pending',
    created_at         TEXT    NOT NULL,
    updated_at         TEXT    NOT NULL
);
CREATE INDEX idx_eval_batch ON evaluation(batch_code);
CREATE INDEX idx_eval_case  ON evaluation(test_case_id);
CREATE INDEX idx_eval_bad   ON evaluation(batch_code, bad_case_flag);
CREATE INDEX idx_eval_code  ON evaluation(code);
```

## 4. 数据安全与运维说明

| 项目 | 说明 |
| --- | --- |
| 敏感加密 | `pre_diagnose_report` 病史类、`message.content`、`evaluation.input_text` 如需加密在应用层处理（可对应 `*_enc` 字段承载密文） |
| 备份容灾 | sqlite 文件定时备份 + WAL checkpoint；支持导出恢复 |
| 分页查询 | 消息/会话列表均按 `created_at` 倒序分页，避免全量加载 |
| 预留迁移 | 表结构遵循关系范式与索引设计，未来可平移至 MySQL/PostgreSQL（替换 `AUTOINCREMENT` 等方言差异） |
| 数据合规 | 会话/报告/消息均支持按用户软删与物理删除（合规 PR-08），日志脱敏 |

## 5. 指标统计口径（与评测联动）

| 指标 | 统计口径 | 涉及字段 |
| --- | --- | --- |
| 科室推荐 Top3 准确率 | 命中用例数 / 总用例数；逐条由 `top3_accuracy` 标记 | `evaluation.top3_accuracy`、`pre_diagnose_report.recommend_dept_top3` |
| 关键信息追问覆盖率 | 命中要素数 / 期望要素数，逐条由 `field_coverage` 记录 | `evaluation.field_coverage`、`conversation.ask_progress` |
| 报告字段完整率 | 非空必填字段数 / 必填字段总数，逐条由 `report_completeness` 记录 | `evaluation.report_completeness`、`pre_diagnose_report.*history 字段` |
| 平均响应时间 | 单样本平均响应时延 | `evaluation.avg_response_time` |

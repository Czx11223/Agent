# 系统集成与前后端联调部署文档

- 版本：V1.0.0　·　环境：Windows 11 / 本地开发（PowerShell）
- 组成：AgentScope Agent + FastAPI 后端 + React 前端 + sqlite3 数据库
- 前置交付：见 `backend/`（09~14）与 `frontend/`（15~17）文档

> ⚠️ 生产环境必须启用 HTTPS（后端已用 `[TLS]` 标注安全边界）；本文档面向**本地联调**。

# 第 2 章 本地部署完整步骤

## 2.1 环境安装

| 依赖 | 版本要求 | 说明 |
| --- | --- | --- |
| Python | 3.12+ | 后端运行 |
| Node.js | 18 及以上（建议 20 LTS） | 前端构建 |
| Git（可选） | — | 拉取语料/示例 |
| 浏览器 | Chrome / Edge / Firefox / Safari 最新两版 | 前端访问 |

```powershell
# 校验版本
python --version
node -v
npm -v
```

## 2.2 初始化后端

```powershell
cd <项目根>\backend

# 1) 创建并激活虚拟环境
python -m venv .venv
.\.venv\Scripts\Activate.ps1

# 2) 安装依赖
pip install -r requirements.txt

# 3) 复制环境变量样例并按需填写 LLM API Key
Copy-Item .env.example .env
# 编辑 .env，设置：
#   JWT_SECRET=<随机长密钥>
#   LLM_API_KEY=sk-xxxx
#   LLM_BASE_URL=https://<国内可直连OpenAI兼容端点>/v1
#   LLM_MODEL=<模型名>
# （PowerShell 也可用 $env: 临时设置）
```

`.env.example` 内容：

```bash
JWT_SECRET=please-change-me-to-a-long-random-secret
LLM_API_KEY=sk-xxxx
LLM_BASE_URL=https://your-llm-endpoint/v1
LLM_MODEL=your-model-name
DB_PATH=./app.db
```

## 2.3 数据库初始化

```powershell
# 方式A（推荐，独立初始化）
python -m app.db.init_db

# 方式B：启动应用时由 main.py lifespan 自动建表(init_db)
# 初始化成功会在 backend/ 下生成 app.db (WAL模式)
```

> 建表脚本与步骤1《数据库设计》五张表一致（`user/conversation/message/pre_diagnose_report/evaluation`）。

## 2.4 启动后端

```powershell
# 仍在 backend 且 .venv 已激活
uvicorn app.main:app --host 0.0.0.0 --port 8000 --reload
```

验证：浏览器打开 `http://127.0.0.1:8000/docs` 可见 Swagger UI；`GET /health` 返回 `ok`。

## 2.5 启动前端

```powershell
cd <项目根>\frontend
npm install
npm run dev        # 默认 5173,Vite 将 /api 代理到 http://127.0.0.1:8000
```

访问 `http://127.0.0.1:5173`，注册→登录→进入主对话页开始联调。

> 生产构建：`npm run build` 产出 `dist/`，由 Nginx 托管并把 `/api` 代理到后端（HTTPS，见 `deploy/nginx.conf`）。

# 第 4 章 常见故障排查清单

| 症状 | 可能原因 | 排查 & 处理 |
| --- | --- | --- |
| **LLM 调用失败（5001）** | ① LLM Key/BaseURL/Model 配置错误 ② 国内不可直连 ③ 额度/限流 ④ 请求超时 | ① 核对 `.env` 与 `client.py` 读取；② 换可直连端点；③ 检查账户额度与 QPS；④ 调大超时时长或重试；看后端日志定位 HTTP 状态 |
| **SSE 流式断连 / 只出首帧** | ① 代理缓冲了响应 ② 反向代理无 `X-Accel-Buffering:no` ③ 断点续读失败 | ① 后端已设 `X-Accel-Buffering: no`；Nginx 再加 `proxy_buffering off`；② 确认客户端用 fetch 流式（不能用 EventSource 发 POST）；③ 网络代理/防火墙不要缓存 `text/event-stream` |
| **SSE 收到但不渲染** | 前端 `sse.ts` 解析的事件名不匹配 | 检查事件字段为 `{type,...}`（事件名在 `data` 内）；按 `ev.type` 分支；打印原始流核对 |
| **数据库报错 / 建表失败** | ① `app.db` 损坏/被占用 ② 权限 ③ 连接未 commit | ① 停止进程删除 `app.db`-wal 后重建；② 用管理员或可写目录；③ 确保 `tx()` 提交；开启 `PRAGMA foreign_keys=ON` |
| **sqlite 锁 / busy** | 多线程并发写 | 已用 WAL + 每线程连接；若仍 busy 加 `busy_timeout`，或降低并发 |
| **跨域 CORS（浏览器报错）** | 前端 5173 与后端 8000 非同源，且未走代理 | 开发用 Vite `/api` 代理（同源）最省事；直接跨源时后端 `allow_origins` 需只放前端真实域名（勿用 `*`+credentials） |
| **401 / 越权 4004** | 令牌过期 / 未带 Authorization / 访问他人会话 | 重新登录取新 token；前端拦截器统一加 Bearer；检查 `user_id` 归属 |
| **登录访问 `/chat` 跳登录** | token 未写入 localStorage | 确认 `api.ts` 的 `TOKEN_KEY` 写入；登录返回 `token` 字段 |
| **报告接口 404"尚未生成"** | 追问未完成就查报告 | 先完成全部关键槽位，等 `done.next=report_ready` 再拉取 |
| **提示词注入被误拦（4007）** | 输入含"忽略/扮演/系统prompt"等 | 属预期拦截；确为误报可调整 `_INJECTION_PATTERN` |
| **响应 >5s** | LLM 推理慢 / 无流式 | 确认走流式降低首帧感知；换更快模型；检查网络往返 |

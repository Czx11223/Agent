# 性能优化方案 + Bad Case 迭代策略

- 版本：V1.0.0　·　目标：稳态满足 **平均响应 ≤ 5s**、追问覆盖率≥90%、报告完整率≥90%、科室Top3≥80%

---

## 第 1 章 性能优化：降低 LLM 响应耗时（≤5s）

### 1.1 分层优化思路

```
成因分析: 耗时 ≈ 网络RTT + Prompt预处理 + LLM推理(主要) + 输出传输 + 业务后处理
优化主线: ①减少Prompt体积 ②降低推理出词量 ③缩短首token ④并行/缓存 ⑤降级
```

### 1.2 模型与推理侧（收益最大）

| 手段 | 说明 | 预期收益 |
| --- | --- | --- |
| **启用 SSE 流式** | 首 token 见底，感知时延大降（已实现） | 首帧 < 1s 可接受 |
| **精简 System Prompt** | 压缩人设+追问链+规则为结构化精简版，减少每轮输入 token | 显著 |
| **控制 `max_tokens`** | 追问/安抚话术定长（100~200），报告生成时才放宽 | 中等 |
| **低 `temperature`** | 0.2~0.3，减少采样重试，输出更稳定 | 小 |
| **换更快/更小模型** | 追问路由用轻模型(快)，报告生成用强模型(慢但有兜底超时) | 大 |
| **请求级超时+重试** | LLM 侧设 timeout，超时降级返回模板话术 | 兜底 |
| **负载均衡/批处理** | 高并发时对 LLM 请求做并发上限与队列（防限流重排队） | 稳定性 |

### 1.3 应用层：缓存策略

| 缓存对象 | 策略 | 说明 |
| --- | --- | --- |
| **语义缓存（追问回复）** | 对话历史相同问题+相同槽位 → 复用上次追问话术 | 用 `槽位指纹(语义hash)` 命中即免调 LLM |
| **症状-科室映射缓存** | 映射表预热进内存（开机加载 JSON），科室推荐免 LLM | 命中即秒回 |
| **模板/话术缓存** | 追问/安抚/拒答/急诊模板常驻内存轮换 | 免生成 |
| **字符串内联缓存** | Python lru_cache 包装低频纯函数 | 小 |
| **CDN/静态资源** | 前端 dist 走 CDN，压缩+gzip | 首屏 |

> 语义缓存示例：主诉→归一化 key（去掉停用词/同义词典）→ 若已存在对应追问与槽位，直接返回缓存话术并推进，跳过 LLM 调用，时延可降至毫秒级。

### 1.4 数据层与前端

- **sqlite**：WAL + `busy_timeout` + 索引（`conversation_id`、`message.sender`），事务批写。
- **前端**：SSE 边收边渲染（不要等整包）；报告/映射懒加载；长列表虚拟滚动。

### 1.5 验收口径

- 定义"平均响应"= 单轮从提交到**完整回复**的平均时延（报告与追问均统计）。
- 分级：追问类目标 ≤3s（流式首帧更早）；报告生成退化为异步时可接受稍长，但整体平均必 ≤5s。

## 第 2 章 Bad Case 迭代策略

### 2.1 闭环流程

```
评测(bad case) → 分类归因 → 定向修改(提示词/映射/话术) → 回归评测 → 判定达标? 否→回到分类; 是→发布固化
```

### 2.2 Bad Case 分类与归因

| bad 标签 | 现象 | 典型归因 | 优化入口 |
| --- | --- | --- | --- |
| `coverage` | 期望要素未采到 | 问法未覆盖/指代未消解/患者答非所问 | 提示词+话术 |
| `top3` | 科室推荐未命中 | 症状-科室映射缺失/加权偏差/专科未识别 | **映射表**+规则 |
| `report` | 字段缺失 | 兜底缺失/追问未闭环 | 提示词+模板 |
| `emergency_mis` | 急重症漏判/误判 | 急诊关键词不全/缩写/误触发 | 提示词+急诊规则 |
| `timeout` | 响应超时 | LLM 慢/无缓存/未流式 | 性能方案 |

### 2.3 提示词迭代方法

1. **收集失败对话**：导出该 bad case 的完整多轮 transcript 与最终槽位。
2. **定位缺失**：标注哪个要素没采到、模型为何回退。
3. **定向改写**：
   - 缺追问 → 在 Prompt 追问链中补"若未提及 X 则必追问一次"；
   - 误诊/越界 → 强化"只预问诊、不做诊断、不开药"约束示例；
   - 指代 → 加"沿用上文部位/时间"示例（"也是这里疼"）。
4. **加 Few-shot 示例**：把失败输入的"期望回复"作为例证加入 Prompt（1~3 条，勿让 Prompt 过长）。
5. 回归整套测试集，确认修复无副作用（防"修好一个打破一片"）。

### 2.4 症状–科室映射表迭代方法

1. **导出未命中 top3 的症状词** → 到映射表查 MISS。
2. **补映射行**：新增 `症状关键词列表`（含同义词/俗称，如"胸口闷"↔"胸闷"），配 推荐科室1/2/3。
3. **调加权权重**：多症状冲突时，观察主要症状 rank1 是否被 `伴随` 抢权——若反复，降低伴随权重(0.6→0.5)或提高"交集强化"。
4. **急重症扩充**：把漏判的急症词加入急诊关键词库（"透不过气/咯血/不省人事/大出血"），并置于最高优先级一票否决。
5. **归一化词典维护**：症状别名统一到标准词，确保命中稳定。

### 2.5 回归与发布标准

- 每次改动必须全量重跑评测集，对比四指标 **不劣化**（尤其 Top3/P）；
- 达标判定：覆盖率≥90%、完整率≥90%、Top3≥80%、均响应≤5s，急重症拦截 100%；
- 通过后固化版本号（Prompt v+1、映射 v+1），写入评测报告。

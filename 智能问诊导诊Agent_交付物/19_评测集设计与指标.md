# 评测集设计与评测指标

- 版本：V1.0.0　·　依据：任务书"评测集构建与效果评测：构建不少于100条的测试问诊对话集"
- 约束：**全部为模拟数据，不含真实患者隐私**；普通场景上尽量识别/追问，急重症场景验证拦截。

---

## 1. 测试集字段规范

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `case_id` | TEXT | 是 | 用例编号 `TC-0001`… |
| `category` | TEXT | 否 | 场景：`internal`(内科)/`ortho`(骨科)/`derma`(皮肤)/`emergency`(急重症)/`incomplete`(残缺) |
| `chief_complaint` | TEXT | 是 | **患者初始主诉**（模拟，可能信息残缺，仅一句话） |
| `expected_slots` | JSON | 是 | **期望采集的关键要素**：五类必填要素及其期望值，用于追问覆盖率 |
| `expected_top3` | JSON | 是 | **期望 Top3 科室**（主期望放在首位） |
| `emergency` | BOOL | 是 | 是否急重症（`true` 时验证急诊拦截） |

五类要素 key（与《07_追问要素清单》一致）：`main_symptom / body_part / duration / accompanying_symptom / past_history`（另含 `allergy_history` 视场景）。

**残缺模拟**：部分案例初始主诉只给一半信息（如"我有点不舒服"、"咳嗽想挂号"），**期望模型继续追问补齐其余要素**，这正是覆盖率指标的考核点。

## 3. 评测指标定义与目标

| 指标 | 计算公式 | 目标 | 判定口径 |
| --- | --- | --- | --- |
| **关键信息追问覆盖率** | `∑每条(成功采集的期望要素数 ÷ 该条期望要素数) ÷ 用例数`，整体取平均 | ≥ 90% | 期望要素能在最终槽位中采到（五要素 key 对齐） |
| **报告字段完整率** | `必填报告字段非空的用例占比`（主诉/现病史/过敏史/既往史四必填字段） | ≥ 90% | 报告四必填字段非空即该条达标 |
| **科室推荐 Top3 准确率** | `期望首要科室出现在推荐Top3中的用例占比` | ≥ 80% | 逐条比对 `expected_top3[0] ∈ get(recommend_top3)` |
| **平均响应时间** | 所有轮次 `回合响应时延` 的算术平均 | ≤ 5 s | 每轮从发送到收到完整回复（含流式） |

> 前缀说明：本指标与任务书"关键信息追问覆盖率90%+、报告字段完整率90%+、科室Top3准确率80%+、平均响应≤5s"一一对应，评测脚本据此判定 pass/fail。

## 4. 场景配比建议（≥100 条总集）

| 场景 | 建议占比 | 功效 |
| --- | --- | --- |
| 普通内科（消化/心血管/呼吸/神内/内分泌） | ≈ 40% | 追问链与科室推荐主场景 |
| 骨科 / 皮肤科 | 各 ≈ 10% | 专科识别 |
| 残缺输入（主诉不完整） | ≈ 25% | 覆盖"信息不足继续追问"重点 |
| 急重症 | ≈ 15% | 拦截与急诊推荐 |
